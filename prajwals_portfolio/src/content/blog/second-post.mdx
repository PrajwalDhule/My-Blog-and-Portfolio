### So What is Image Dithering?

Simply, It is a method to represent an image with a fewer/limited set of colors.
It involves a process called *quantization*, which is basically rounding pixel values to their closest value in a smaller set of values.
In addition, there are some algorithms that involve *error diffusion*, which is the process of spreading errors (difference between original and quantized pixel value) to nearby pixels.

It's a way to create an illusion of smoothness with a smaller set of colors by strategically adding noise or "dots". 
Other than being a really cool visual effect generator, there are other use cases as well.

### Some Use Cases of Image Dithering

It's earlier use cases were in newspapers, comic books, and other printed media, where dithering would be applied to images using just black dots (and white using absence of black). This would smoothly simulate gray shades even though printing presses only supported black ink.
Comic books and other color printing worked similarly, but to simulate more shades of color than the limited palette printing presses had.

### Some Common Dithering Algos and how they work
Let's now explore how some of these algorithms work, it's also helpful if you want to implement them yourself.
I will focus on two main categories:

#### Error Diffusion Algorithms

Here, we first quantize the colors and round them to the closest value. Then we take the difference between the original and the quantized value, which is the *error* and spread it to nearby pixels. There are different algorithms to spread these errors, let's go through some of them:

##### Floyd-Steinberg Algorithm

-> It traverses from left to right in the image and pushes the quant error to the neighbouring *four* pixels like shown below:

-> let's say we have a pixel value in RGB format with <code>R value = 207</code> and we round it to <code>255</code>, so the quant error is <code>255 - 207 = 48</code>. 

<blockquote class="small-note"> We can decide what value to round off to and how many color values we want, for e.g. if we wanted n = 4 values in our dithered image - <code>0,  85, 170, 255</code>. In this case, a value of <code>207</code> will be rounded off to the closest one i.e. <code>170</code>. </blockquote>

-> now according to the coefficients shown previously, the pixel to the right will be transformed to <code> newValue = oldValue + error * 7/16</code>, if the value of that pixel was <code>150</code>, it will change to <code>150 + 48 * 7/16 = 171</code>.

In short, for every pixel: 
1. round off value to <code>closestValue</code>.
2. calculate <code>error = closestValue - value</code>.
3. for each of the neighbours, <code>newValue = oldValue + error * itsCorrespondingFraction</code>.

<blockquote class="small-note"> Note: <code>RGB values range from 0 to 255</code>. In grayscale images, a pixel's R, G and B values are all the same, so (207, 207, 207) will convert to (255, 255, 255) which is also grayscale. <br/>
It means for <code>n = 2</code> possible values, <code>0 and 255</code>: <br/>
For a grayscale image -> 2 (or n) possible outputs i.e. (0, 0, 0) or (255, 255, 255). <br/>
For a non-grayscale image -> more than 2 (or n) possible outputs e.g. (255, 255, 0), (255, 0, 255), (0, 255, 0), (255, 255, 255) and so on. </blockquote>

<blockquote class="small-note">Also, note that whenever I mention "value" I am referring to one of R/G/B values, which is also referred to as *brightness*.</blockquote>

##### Atkinson Algorithm
Atkinson dithering is a variant of Floyd–Steinberg dithering designed by Bill Atkinson at Apple Computer, and used in the original Macintosh computer.

#### Non-Error Diffusion Algorithms
One of the main type of algorithms here are *ordered* algorithms.
You apply a fixed, repeating pattern (an “order”) to decide how to threshold each pixel. Here, we usually have just *two* colors (two each for R,G, and B) and round off the pixels based on if it's greater or smaller than a dynamic threshold. Examples:

##### Bayer Ordered Algorithm
Ordered algorithms usually utilize a threshold matrix to create a repeating pixelated, grid-like patterns.
Think of it as starting with a matrix of values and repeating it across the entire image, like floor tiles.

--- maybe an image ---

<code class="code-block">
```
// 4 x 4 threshold matrix

const thresholdMat = [
    [  0,  8,  2, 10 ],
    [ 12,  4, 14,  6 ],
    [  3, 11,  1,  9 ],
    [ 15,  7, 13,  5 ]
  ];
```
</code>

-> A matrix is defined, which is usually a square matrix with <code>N x N</code> dimensions and values from <code>0 to N * N - 1</code>. This matrix is also called *Bayer matrix* when N is a power of 2.

-> While traversing each pixel, we can get the corresponding matrix value by taking <code>modulo</code> of the pixel indices (x and y) <code>w.r.t. N</code>.

-> Once we get the value, we <code>divide by N*N</code> to get a value between 0 and 1 and <code>multiply it with 255</code>. 

---- formula image with mention of + 0.5 ----

-> Now we have a *threshold* value to which we compare the original pixel value and decide to turn the pixel *on or off* 

-> For e.g. if the threshold is 127.5 and the pixel value is 130, we can turn it "on" (since 130 > 127.5) by setting it to a value like 255. Thus, ordered dithering usually only has two output color values unlike error diffusion algorithms.

##### Halftone
This algorithm doesn't use a matrix, but can still be termed as an ordered algorithm since it generates similar, repeating patterns — circles.

-> To create a basic halftone effect, we can take a grid or cell of size N similar to Bayer, but instead of comparing pixels to some matrix, we just convert it to grayscale and take it's value (or brightness).

-> For the current cell of N x N pixels, we take the average of those N*N values in a cell to get the average brightness of the cell.

-> we then calculate the radius of the dot/circle to create using <br/>
   <code>radius = ((255 - avg) / 255) * cellRadius</code>.

-> Now, for each pixel outside of this radius w.r.t. the center of the cell, we turn it off, or make it 255 i.e. white, else black i.e. 0.

-> the end result is a black circle at the center of the cell. The resulting image will be made of such circles of different sizes.
